# ADR 0004 — 802.11 scope (settled at the T23a planning pass)

## Status

Accepted (2026-11-06, tranche T23a). Closes the roadmap's open
decision #2 and the backlog's P2 line.

## Context

The wave-2 charter sketch left the 802.11 scope to this pass, with a
recommendation: dissect-only management frames (linktype 105), and
monitor-mode injection recorded out. The use case is capture analysis
(`tcpdump -i wlan0 -y IEEE802_11` files replayed through `wrex
replay`) — the same job the cooked captures serve for `-i any`.

## Decision

**Dissect-only, linktype 105 (LINKTYPE_IEEE802_11):**

- A `dot11` codec (`wrex-proto-dot11`, feature `proto-dot11`): the
  frame-control word (version/type/subtype + the to_ds..order flag
  aggregate), duration, addresses 1–3 (+4 under to_ds|from_ds), the
  sequence word (12-bit seq + 4-bit frag, both craftable), and a
  dissect-only `elt` record section for management information
  elements (`elt.0.ssid`, `elt.1.chan`, … beside the raw
  id/len/value wire truth). ADR-0001's registry shape, ADR-0003's
  parent deps (a root layer — none needed).
- The element region rides the payload verbatim on the craft side
  (dissect-only typing — the deliberate boundary).
- Replay/dispatch: `LINKTYPE_IEEE802_11` → `dot11` start.

**Recorded won't-dos:**

- Monitor-mode injection (sending on a monitor interface is a
  different driver class — radiotap, channel state — never a codec
  concern).
- Radiotap headers (linktype 127): the radiotap TLV space is its own
  mini-language; a future tranche if a corpus demands it.
- Control/data-frame body typing: bodies stay payload.

## Consequences

- The analysis plane covers `tcpdump -i any`-style wifi captures on
  management frames; data-frame payloads surface verbatim (an honest
  boundary for encrypted traffic, which is most of it).
- The G1/G2/G3 gates cover the codec like every other (the frag/seq
  bit windows ride the bit-toggle sweep; the elt records ride the
  record-section rules).
